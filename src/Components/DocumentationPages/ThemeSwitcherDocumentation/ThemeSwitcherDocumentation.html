ThemeSwitcher

Overview

ThemeSwitcher is a single button that cycles through the themes you give it, showing the active theme's name as its value. It is the lightweight counterpart to : use ThemeSelector for a binary LIGHT/DARK toggle with icons, and ThemeSwitcher when you want a compact text control that walks an arbitrary list of themes (e.g. LIGHT → DARK → SOLARIZED → …).

It works in two visual variants — a compact button pill for topbars/toolbars, and a full-width menu-item row for dropdowns and user menus.

Core Behavior

  • themes is the ordered list to cycle through. Each click advances to the next entry and wraps around at the end. Defaults to ['LIGHT', 'DARK'].
  • On switch it calls slice.setTheme(next), dispatches a global themeChanged CustomEvent (so every other theme control on the page stays in sync), and invokes the optional onChange(themeName) handler.
  • It also listens for themeChanged, so changing the theme anywhere else updates the displayed value automatically.
  • variant switches the layout: 'button' (default) hides the caption and renders a pill; 'menu-item' shows the label caption on the left and the value on the right.
  • display maps a theme name to its label and icon, e.g. { LIGHT: { label: 'Light', icon: 'sun' } }. It is opt-in and empty by default, so without it the raw registered theme name (LIGHT, SOLARIZED) is what the user sees. A theme with no entry falls back to its raw name and a generic palette icon, so a custom theme never renders blank.
  • The control renders an icon slot that follows the current theme; an unknown icon name is ignored rather than breaking the button.
  • The document listener is registered in init() and removed in beforeDestroy().

Friendly theme names

By default the switcher prints the registered theme name. display maps a name to what the user should actually read, plus an icon — without renaming the theme itself.

Pitfalls

Language

The built-in texts are slice.themeSwitcher.* keys with English and Spanish defaults, registered by shared/text/texts.js in the translator's lowest layer: an app dictionary always wins, and the component keeps its English text when the translator is off. label and texts still win over the dictionary.
