Shared markdown contract

This parser follows the same contract as slice.js_docs (the reference implementation): MARKDOWN-CONTRACT.md. The same fixtures are covered by parser/tests/markdown-contract.test.js.

Supported Blocks

  • Headings, paragraphs, bold/italic, inline code, links, images
  • Unordered and ordered lists, nested and wrapped
  • Blockquotes and horizontal rules
  • Fenced code blocks -> CodeVisualizer
  • Tables -> Table (links and inline code in cells)
  • :::tip / :::warning / :::note / :::info / :::success / :::danger -> Callout
  • :::callout tone="..." variant="..." title="..." -> Callout
  • :::compare left="Do" right="Don't" -> two Callouts in a Grid
  • :::related with a list of links -> Grid of Cards
  • :::details title="..." -> Details, body parsed as markdown
  • :::component name="Button" with JSON props body
  • :::script ... for interactive prop scenarios

Callout budget: 1–3 per page. Use :::warning only for a real risk; use :::compare for a contrast instead of two separate tips.

SEO Artifacts

docs:generate also writes two files from the same front matter, so they can never drift:

  • src/public/sitemap.xml — one <url> per real page (the generated docRoutes plus /, /docs and /theme-creator), never a section index that has no page. <lastmod> is the markdown file's last commit date (not its mtime), so a fresh clone does not rewrite it.
  • src/public/seo.json — per-route title, description, robots, sitemap and jsonLd. Internal routes (/__test, /playground, /game, /404) carry robots: false so they get served without being indexed, and the same file is what the framework's seo option reads.

Both are generated: edit parser/lib/seo.js or the front matter, never the XML/JSON by hand. parser/tests/seo.test.js fails when the committed sitemap does not match the generated routes.
