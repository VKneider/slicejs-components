Stepper

Overview

Stepper is the single component for an ordered process. mode: 'static' explains how something works. mode: 'interactive' shows where someone is in a task and lets them move between stages. It replaces the earlier separate Steps proposal and implementation; there is no Steps component, alias or compatibility route.

When to use it

Use static mode for a landing page's “How it works”, a setup procedure, or instructions with commands. Use interactive mode for checkout stages, onboarding or a multi-step form. Use Tabs for sibling views with no order/completion, Timeline for events with dates, and TourService for a guided overlay pointing at controls across an existing screen.

Items and modes

items is an array of { id, title, text, icon, content, status, disabled }. IDs are unique strings (numbers normalize to strings); omitted IDs fall back to the index. Supply stable IDs when items change. Duplicate IDs throw a clear error rather than sharing the wrong DOM row.

  • Static mode has an <ol> with headings and decorative number/icon/dot markers. No navigation

controls, current-step announcement or click handlers are added.

  • Interactive mode has real buttons, one aria-current="step" item, state text and a polite

announcement of the active title and position. It remains an ordered list, never a tablist.

  • active is an item ID. By default the first enabled item marked current is selected, or the

first enabled item. One item is current even if input data marks several. Invalid/disabled IDs fall back by the same rule. Static mode exposes active === null.

  • status is upcoming, current, done, or error. active determines the current item;

completion/error are supplied by the app. Clicking does not mark anything done or validate data.

  • linear: true allows completed steps and the first incomplete step, but blocks future steps.

Disabled steps are not actionable. clickable: false makes interactive state read-only; disabled disables all navigation. Programmatic active = id can select any enabled item: the app owns validation and can restore a saved task.

  • select(id) returns true only when a permitted user selection changes the current item. It fires

onChange(id, { previous, step, index }) and bubbling step-change with { id, previous, step, index }. Assigning active does not fire these callbacks. The component does not own panels or routes.

Layout and content

orientation is vertical by default. Horizontal becomes vertical when its container is under 600px. marker is number, icon (number fallback), or dot; start continues the numbering. variant is soft, filled, or outlined, independently of semantic tone. size is sm/md, connector hides/shows joining lines, and headingLevel controls the item headings.

content accepts text, nodes, components or arrays. Strings stay text. Rows and existing icons are reused by ID; assigning items again keeps surviving content nodes, including an editor's draft. Removed/replaced content and icons are destroyed. The component owns the content you give it.

Keyboard in interactive mode: Tab enters the actionable step list once, arrows move focus among enabled steps, Home/End focus the first/last actionable step, and Enter/Space activate the focused native button. Moving focus alone does not select. RTL horizontal arrows follow reading direction.

Examples

Texts and theming

Built-in status/announcement texts use slice.stepper.*: label, upcoming, current, done, error, progress ({index}, {total}, {title}), with English/Spanish defaults. texts overrides app dictionaries; ariaLabel names the list. Titles and descriptions belong to the app.

Colors follow theme tokens; component variables use --slice-stepper-* (color, ink, on-color, marker, gap, space, line). Reduced-motion users get no decorative motion. The component has no network calls, global listeners or timer loop.
